# 推出 MCP 注册表 | 模型上下文协议博客

今天，我们正式推出模型上下文协议（Model Context Protocol，MCP）注册表——一个面向公开 MCP 服务器的开放目录与 API，旨在提升服务器的可发现性与实现效率。通过将服务器的分发与发现方式标准化，我们既扩大了它们的触达范围，也让客户端更容易完成连接。

MCP 注册表现已进入预览（preview）阶段。开始使用：

- 添加你的服务器：请遵循《向 MCP 注册表添加服务器》指南（面向服务器维护者）。
- 获取服务器数据：请遵循《访问 MCP 注册表数据》指南（面向客户端维护者）。

# MCP 服务器的唯一权威来源

2025 年 3 月，我们曾表示希望为 MCP 生态构建一个中心化注册表。今天我们宣布，已正式上线 https://registry.modelcontextprotocol.io 作为官方 MCP 注册表。作为 MCP 项目的一部分，MCP 注册表及其父级 OpenAPI 规范都是开源的——任何人都可以构建一个兼容的子注册表。

我们的目标是将服务器的分发与发现方式标准化，提供一个子注册表可以赖以构建的首要权威来源。反过来，这将扩大服务器的触达范围，并帮助客户端在整个 MCP 生态中更轻松地找到服务器。

## 公开子注册表与私有子注册表

在构建中心化注册表的过程中，对我们而言很重要的一点是：不削弱社区和企业已经构建的现有注册表。MCP 注册表作为公开可用 MCP 服务器的首要权威来源，而各组织可以选择基于自定义标准创建子注册表。例如：

- 与各个 MCP 客户端相关的、有明确取向的"MCP 市场"这类公开子注册表，可以自由地对它们从上游 MCP 注册表摄取的数据进行扩充与增强。每个 MCP 终端用户群体都有不同的需求，如何以有取向的方式服务好各自的终端用户，取决于各 MCP 客户端市场。
- 私有子注册表将存在于对隐私和安全有严格要求的企业内部，但 MCP 注册表为这些企业提供了一个可以构建于其上的单一上游数据源。我们至少会与这些私有实现共享 API 架构（schema），以便相关的 SDK 与工具能在整个生态中通用。

无论哪种情况，MCP 注册表都是起点——它是一个中心化场所，MCP 服务器维护者在这里发布并维护他们自行上报的信息，供这些下游消费者加工并交付给各自的终端用户。

## 社区驱动的审核机制

MCP 注册表是由注册表工作组维护、采用宽松许可协议的官方 MCP 项目。社区成员可以提交 issue 来举报违反 MCP 审核准则的服务器——例如包含垃圾信息、恶意代码，或冒充合法服务的服务器。注册表维护者随后可以将这些条目列入拒绝名单（denylist），并将其从公开访问中追溯移除。

# 开始使用

开始使用：

- 添加你的服务器：请遵循《向 MCP 注册表添加服务器》指南（面向服务器维护者）。
- 获取服务器数据：请遵循《访问 MCP 注册表数据》指南（面向客户端维护者）。

MCP 注册表的这个预览版，旨在帮助我们在正式全面可用（general availability）之前改进用户体验，它不提供数据持久性保证或其他任何担保。我们建议 MCP 的采用者密切关注其开发进展，因为在注册表正式全面可用之前，可能会发生破坏性变更。

随着我们持续开发该注册表，欢迎你在 modelcontextprotocol/registry GitHub 仓库中提供反馈与贡献：讨论（Discussion）、问题（Issue）和拉取请求（Pull Request）都非常欢迎。

我们深深感谢每一位投身于这一基础开源基础设施的人。正是携手共进，我们才能帮助全世界的开发者与组织构建更可靠、更具上下文感知能力的 AI 应用。谨代表 MCP 社区，向大家致谢。
